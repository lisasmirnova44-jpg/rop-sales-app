# РОП · Центр управления продажами

Статический HTML-интерфейс для GitHub Pages + Supabase.

## Что есть
- Обзор: продажи, активные сделки, задачи на сегодня, сделки в риске.
- Планер: задачи, приоритеты, сроки, плановое время, результат и переносы.
- Контроль сделок: код сделки, этап, сумма, риск, следующий шаг.
- Команда: коды сотрудников, план/факт, конверсия и фокус развития.
- Аналитика и черновик отчёта собственнику.
- Экспорт данных JSON и сделок CSV.
- Демо-режим в браузере и подключение к Supabase.

## Важное ограничение безопасности
Выбранный режим «общая ссылка без входа, одинаковые права» означает, что любой человек, получивший ссылку, потенциально может читать, изменять и удалять общие данные. Публичный anon/publishable key не защищает таблицы сам по себе. SQL-политики в `schema.sql` намеренно открывают доступ, чтобы режим без входа работал.

**Не используйте эту конфигурацию для реальных клиентских данных Lavella:** имён, телефонов, адресов, переписки, договоров, точных клиентских заметок, платежной информации или коммерческой тайны. Используйте только обезличенные коды и неконфиденциальные данные. Если нужны реальные данные, переключитесь на Supabase Auth и закрытые RLS-политики.

## Запуск локально
Можно открыть `index.html` напрямую, но для подключения библиотек и стабильной работы предпочтительно запустить простой локальный сервер или использовать GitHub Pages.

## Настройка Supabase
1. Создайте отдельный проект Supabase.
2. Откройте SQL Editor.
3. Скопируйте и выполните весь `schema.sql`.
4. В настройках API проекта скопируйте Project URL и публичный publishable key (или legacy anon key). Никогда не используйте `service_role` key в браузере.
5. Откройте приложение → «Подключение» → вставьте URL и публичный ключ → «Подключить и загрузить».
6. Создайте тестовую задачу и тестовую сделку. Откройте приложение в другом браузере/устройстве и проверьте, что данные синхронизируются.

Если приложение не подключается, проверьте SQL, правильность URL/key, наличие таблиц и ошибки в консоли браузера.

## Публикация на GitHub Pages
1. Создайте новый GitHub-репозиторий, например `rop-sales-app`.
2. Загрузите `index.html`, `schema.sql` и `README.md` в корень репозитория.
3. В GitHub откройте Settings → Pages.
4. В разделе Build and deployment выберите Deploy from a branch.
5. Выберите ветку `main`, папку `/ (root)`, затем Save.
6. Дождитесь публикации. Адрес будет показан в разделе Pages.
7. Откройте ссылку, подключите Supabase и проверьте с другого устройства.

## Обновление
Измените `index.html` локально и загрузите новую версию в репозиторий. GitHub Pages опубликует обновление автоматически после завершения сборки.

## Перед реальным запуском
- Не публикуйте данные сотрудников/клиентов в публичной базе.
- Удалите демонстрационные записи и замените их обезличенными.
- Включите Auth и закройте публичные политики, если приложение будет содержать рабочие данные.
- Настройте роли: собственник, РОП, продавец; доступ продавца к собственным сделкам и задачам.
- Подумайте о журнале аудита, резервном копировании и ограничении удаления.
